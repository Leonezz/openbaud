# OpenBaud public launch kit

Use this kit to adapt the same verified demo to each community. Do not paste
identical promotional copy across platforms, request upvotes, or imply that the
generated radar scene came from a physical radar sensor.

## Shared facts

- Project: OpenBaud
- Repository: <https://github.com/Leonezz/openbaud>
- One-line value: Turn serial hardware into reusable, auditable tools for
  coding agents.
- Demo hardware: real ESP32-S3 development board over Espressif USB Serial/JTAG
- Demo protocol: OBP/1, a new CRC-protected binary protocol
- Evidence: eight real exchanges, 196 bytes each, 36 parsed records, zero CRC
  failures, lossless capture, hardware-free replay
- Disclosure: the board and serial traffic are real; the radar scene is
  generated by the test firmware and marked `simulated_scene=1` on the wire
- Primary asset: `docs/assets/openbaud-pv.mp4`
- Inline preview: `docs/assets/openbaud-pv-demo.gif`
- Reproducible example: `examples/pv-demo/`

## Reddit engineering-post outline

Suggested title direction:

> I built an auditable serial-device layer for coding agents, then tested it
> with a new protocol on a real ESP32-S3

Write the post in the author's own voice:

1. Describe the original failure mode: a successful serial exchange disappears
   into chat history or a one-off script.
2. Show OBP/1's ten-byte request and 196-byte response layout.
3. Explain that the command validates CRC before decoding the 36-record array.
4. Link the lossless capture and one-command replay, so readers without hardware
   can challenge the claim.
5. State the generated-scene disclosure clearly.
6. Ask for difficult serial devices or protocol captures, not votes.

For `r/rust`, focus on the Rust runtime, framing/checksum/parser design, and
cross-platform packaging. For robotics communities, use the radar/timeline
visual and discuss driver-regression replay. For embedded communities, check
the current self-promotion rules and ask moderators before linking the project.

## Hackaday / Hackster outline

Lead with the bench workflow, not “AI + hardware”:

1. Physical board and USB identity
2. Why OBP/1 was designed
3. Exact frame table and CRC
4. Capture evidence and decoded radar scene
5. Command YAML and provenance
6. Device restoration to ECHO
7. Replay on a computer with no board attached

Include the protocol table from `examples/pv-demo/protocol.md`, the poster, and
the 46-second video. Hackster-style versions should add firmware build/flash
steps before calling the piece a tutorial.
