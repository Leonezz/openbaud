# OBP/1 demo protocol

OBP/1 is a deliberately small binary protocol created for the OpenBaud public
demo. It runs on a real ESP32-S3 development board and exists to make the whole
serial-knowledge loop reproducible: capture, checksum, typed parsing,
visualisation, command sedimentation, and hardware-free replay.

The transport and bytes in the included capture came from the physical board.
The radar scene is generated by the test firmware, not by a connected radar
sensor. Every response states this on the wire with `flags & 0x01 == 1`.

## GET_RADAR request

Ten bytes, with little-endian integers:

| Offset | Size | Field | Value |
| ---: | ---: | --- | --- |
| 0 | 2 | magic | ASCII `OB` |
| 2 | 1 | version | `1` |
| 3 | 1 | opcode | `0x01` |
| 4 | 2 | sequence | host chosen |
| 6 | 2 | payload length | `0` |
| 8 | 2 | CRC-16/Modbus | bytes 0–7 |

## RADAR response

The response is 196 bytes. Its 36 records are five bytes each.

| Offset | Size | Field |
| ---: | ---: | --- |
| 0 | 2 | magic, ASCII `OB` |
| 2 | 1 | version, `1` |
| 3 | 1 | kind, `0x81` |
| 4 | 2 | echoed sequence |
| 6 | 2 | total length, `196` |
| 8 | 4 | board uptime in milliseconds |
| 12 | 1 | point count, `36` |
| 13 | 1 | flags; bit 0 means generated test scene |
| 14 | 180 | records: angle centidegrees, distance mm, intensity |
| 194 | 2 | CRC-16/Modbus over bytes 0–193 |

The command spec intentionally decodes the records as an array rather than
hiding them in custom code.
